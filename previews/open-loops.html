Scope and proposed host

Swipes choose a delay or a task; only explicit quest acceptance earns XP. This preview uses fixtures. The proposed macOS host is Tauri v2: a restricted WebView, Rust-owned commands/state, a packaged Swift AX/ScreenCaptureKit helper, SQLite memory, Keychain credentials and one approved provider. Custom commands require AppManifest permissions plus per-window capabilities and Rust validation. The Mermaid view gives the executable build order; none of those native integrations exists in this HTML.

240 minutes, not a roadmap

  1. 0–25 · 25 min: access, source request, evidence and write-destination gate. If missing, stay in fixtures.
  2. 25–70 · 45 min: bounded Snowflake view, provenance and owner.
  3. 70–150 · 80 min: buddy, choices, exact preview, confirm/cancel, receipt.
  4. 150–195 · 45 min: visible-session idle badge and measurement.
  5. 195–240 · 45 min: keyboard/mobile, success, stale evidence, permission denial and failed-write proof.

Read access is not write access

Snowflake is a replicated read layer. A live action needs an existing authorized source API, explicit human approval, current source status/version, and scoped permission. Re-check immediately before writing. Already closed, changed, or missing evidence means stop. Use a stable action ID; reconcile a timeout before retrying. Only source success plus authoritative readback proves closure.

Measure the actual question-to-decision

Time question to decision: decision_confirmed_at − question_submitted_at, wall-clock seconds from question submission through evidence retrieval, reading and explicit confirmation. Median/p90, split by action. Cancellations separate; execution latency separate; simulations excluded.

Stale requests closed per week: distinct source request IDs at least 30 days old since creation, open before action, authoritatively confirmed closed by the agent in a Monday–Sunday UTC week. Exclude simulations, already-closed records, deferrals, failed/unverified writes and reopened requests; deduplicate retries.

Category: Something that makes the business run better — faster question-to-decision workflows. No observed productivity gain claimed. Design: Tailwind v4 + DaisyUI v5 fallback; no existing app supplied.
